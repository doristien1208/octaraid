# 八方討伐 (octaraid)

FF14-style 3D raid game for colleagues on the office LAN. 1–8 players (usually 3–4) create a room or join one with a 4-character invite code (there is no lobby), pick one of 8 jobs (2 tanks, 2 healers, 4 DPS; 5 skills each plus a shared Limit Break), vote on one of 8 "duty + difficulty" options, and fight a boss whose mechanics follow a fixed timeline. Planning doc (Claude Doc): https://claude.ai/code/artifact/dd4ddb06-eea7-4b00-b1e9-02e6bc31219c — keep it in sync when rules or protocol change.

## Constraints
- Node.js 22.18.0 everywhere (`.nvmrc`): the test machine runs exactly this. Don't rely on newer Node APIs. `CLAUDE.local.md` says how to get this version on the dev machine.
- The GitHub repo is public: the test machine's IP, the share and anything personal stay in `CLAUDE.local.md` (gitignored).
- Numbers are tuned for 3–4 players: boss HP = 4-player HP × Σ role weights ÷ 3.2 (tank 0.65, healer 0.55, DPS 1). Mechanic counts are designed for 4 players and scale with the party. No fight may run past 8 minutes (enrage at most 8:00).
- Test machine: Windows. This game uses port 3100 and lives in the share's `octaraid` folder; the Game Hub (sibling project `../GameHub`) starts and watches it, so updates go through its `maintenance.txt` flow. IP, share and Hub details are in `CLAUDE.local.md` (gitignored). Adding the game to the Hub's live `hub.config.json` changes another project: ask first.
- `deploy/start-server.bat` and `deploy/open-firewall.bat` stay plain ASCII with CRLF (`scripts/package.mjs` enforces both); Chinese text goes in `deploy/README-DEPLOY.txt`.
- Art: CC0 assets (KayKit Adventurers + Character Animations, downloaded 2026-10-08, 28 MB) for the characters; bosses, arenas, telegraphs and effects are built in code. `scripts/pack-models.mjs` turns the two packs into `client/public/models/*.glb` (only what is used); the packs themselves are not kept, download them again from the CREDITS.md links to rebuild. Ask before every download (file name, source, size), one pack at a time, under 2 GB in total. Never use Square Enix names, art, music or trademarks.
- Numbers are 暫定 and tuned with `tests/balance.test.ts` (bot parties against each duty's HP): a skill's `fx` and its `desc` in `shared/jobs.ts` must say the same thing, and the doc's job tables follow both.
- Nickname only: no accounts, leaderboard or shop. Text chat is required (colleagues cannot rely on voice).
- `sirv` reads the file list when the server starts: restart the server after rebuilding the client.

## Commands
- `npm run dev` — server on :3100 + Vite on :5174
- `npm test` — vote, invite codes, party and HP scaling, movement validation, combat rules (`tests/combat.test.ts`), each mechanic (`tests/mechanics.test.ts`), bot parties clearing 崩岩巨像 Normal and Hard (`tests/colossus.test.ts`) and the dummy duties with each job's damage (`tests/balance.test.ts`), key settings, the playback clock, a real WebSocket session
- `npm run typecheck`, `npm run build`, `npm start`, `npm run package` (→ `release/octaraid-server`)

## Layout
- `shared/constants.ts` VERSION and RULES; `shared/jobs.ts` the 8 jobs, skills and LB; `shared/encounters.ts` the 4 duties and the 8 vote options; `shared/party.ts` role caps, HP scale, missing-role notes; `shared/vote.ts`; `shared/roomcode.ts`; `shared/protocol.ts`
- `shared/sim/fight.ts` authoritative fight at 30 Hz: countdown, client-reported movement validated against speed and arena (moving cuts casts; stunned players cannot move), skill requests (`use`: checked, queued in the last 0.5 s, cast, executed from each skill's `fx`), damage, healing, statuses, zones, enmity, the Limit Break, enemies (spawn, chase, autos, despawn), the dummy's moves, the end. `shared/status.ts` buffs and debuffs (new ones go at the end: snapshots index them)
- `shared/sim/boss.ts` the boss engine (`BossBrain`): runs a `BossScript` (phases by HP or until the adds are gone, timeline entries with loops, the enrage cast), schedules each mechanic with its telegraph (hidden ones in Hard), resolves hits, marks mistakes and gives the clean-mechanic LB bonus; `shared/sim/mech.ts` shapes and `inside()`. `shared/bosses/` one file per boss script (`colossus.ts`), `foes.ts` every enemy kind, `index.ts` which duty has a script
- `shared/sim/bot.ts` computer players (sandbox and tests): read the hazards (hidden ones too), plan where to stand (spread slots, stack groups, knockback edges), swap tanks, time mitigation, heal, raise, break prisons, kill adds. `shared/sim/practice.ts` the dummy. `shared/sim/arena.ts`: metres, x east, z south, boss at (0, 0), facing f points along (sin f, cos f); ranges are measured from the target's ring (`reach`)
- `server/hub.ts` sessions and rooms by invite code; `server/room.ts` waiting room, tally, fight loop (a snapshot every tick); `server/app.ts` HTTP, `/ws` (Origin check) and `/healthz` (the Hub reads `version`, `online`, `playing`)
- `client/main.ts` screen switching; `client/ui/entry.ts`, `client/ui/room.ts`; `client/game/view.ts` the 3D fight (input, targets, events into animations, effects and numbers), `assets.ts` loads the KayKit files and recolours textures, `look.ts` each job's model, colours, weapons, extras and clips, `avatar.ts` a character with its animation layers (upper body plays skills while the legs run), `models.ts` the dummy and the code-built fallback characters, `bosses.ts` the code-built enemies (崩岩巨像, 岩巨兵, 岩牢, the dummy) behind one `FoeView`, `telegraphs.ts` the ground telegraphs and head markers from snapshot `tg`, `effects.ts`, `arena.ts`, `camera.ts`, `hud.ts`, `playback.ts` (from 水球大亂鬥); `client/sandbox.ts` offline practice (`?sandbox&boss=0..3&hard&n=1..8&job=<id>&dummy&calm&lb&skip=<s>&until=<move>`, `?sandbox&gallery` lines up all 8 jobs)
- `VERSION` in `shared/constants.ts` shows on the entry screen and in `/healthz`; bump it with `package.json` for each release
